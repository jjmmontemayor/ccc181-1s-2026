Information architecture

What information architecture is

Definition

The structure of an app's content: how it is grouped, named and connected, so users can find what they need and understand where they are.

Organization

How content is grouped: by task, audience, topic or time

Labeling

What things are called, in the users' words

Navigation

How users move between parts and know where they are

Search

How users look things up when browsing is not enough

The four systems: Rosenfeld, Morville & Arango, Information Architecture (4th ed., 2015)

06

Wireframes

Wireframes and levels of fidelity

A wireframe is a simplified sketch of a screen that shows layout, content and hierarchy, without final colors or styling.

Low fidelity

Paper or whiteboard boxes. Minutes to make, easy to throw away.

Use for: exploring many layouts

Paper, Excalidraw

Mid fidelity

Digital grayscale layout with real labels and content.

Use for: agreeing on structure

Figma, Balsamiq, Penpot

High fidelity

Final look: color, type, images; often clickable.

Use for: usability tests, handoff

Figma prototypes

Rule of thumb: the less sure you are, the lower the fidelity. Do not polish a layout you have not tested.

Responsive design

Responsive design, mobile first

1 · Viewport meta tag

Without it, phones show a shrunken desktop page

2 · Fluid layouts

Flexbox, Grid, percentages instead of fixed pixel widths

3 · Flexible media

img { max-width: 100%; height: auto; } (Bootstrap: .img-fluid)

4 · Media queries

Adjust layout where the content starts to look wrong

Mobile-first CSS

/* phone: the default */
.position { font-size: 4rem; }

/* wider screens add changes */
@media (min-width: 768px) {
  .position { font-size: 6rem; }
}

Start with the smallest screen: it forces you to decide what matters most.

Touch targets: make buttons at least 44×44 CSS px for thumbs.

Accessibility

Accessibility: WCAG and the POUR principles

1.3B

people, about 16% of the world, live with a significant disability.

WHO, Disability fact sheet (2023)

Plus situational limits: bright sunlight, one hand busy, a cracked screen, slow data.

The Web Content Accessibility Guidelines (WCAG) 2.2 are the standard. Aim for level AA.

Perceivable

Text alternatives, captions, enough contrast

Operable

Works by keyboard; enough time; no traps

Understandable

Clear language, predictable, helps fix errors

Robust

Valid, semantic code assistive tech can read

W3C, WCAG 2.2 (2023) · World Health Organization (2023)

22

Accessibility

ARIA: filling the gaps HTML leaves

The first rule of ARIA

If a native HTML element already does the job, use it instead of adding ARIA.

ARIA (Accessible Rich Internet Applications) adds roles, names and states that assistive technology reads. It changes what is announced, never how things behave.

Wrong ARIA is worse than none: it announces things that are not true.

Three attributes you will use

<!-- icon-only button needs a name -->
<button aria-label="Open menu">☰</button>

<!-- announce updates politely -->
<p id="position" aria-live="polite">
  Position: 4</p>

<!-- state of a toggle -->
<button aria-expanded="false">
  Clinic hours</button>

W3C, Using ARIA · WAI-ARIA Authoring Practices Guide

23

Accessibility

Testing for accessibility

1 · Automated

Scan the page

Lighthouse (built into Chrome DevTools), WAVE, axe DevTools

Catches contrast, missing alt and labels, bad structure

2 · Keyboard only

Put the mouse away

Tab through the page. Can you see focus? Reach and use everything? Escape a modal?

3 · Screen reader

Listen to it

NVDA (free, Windows), VoiceOver (Mac, iPhone), TalkBack (Android)

Automated tools find only part of the problems. A perfect Lighthouse score does not mean the page is accessible.

Interactivity

Design every state, not just the happy path

Loading

“Checking your place…”

Spinner or skeleton; never a frozen screen

Empty

“No one is waiting. Walk right in.”

Explain and suggest the next step

Error

“Couldn't connect. Retrying in 15 s.”

Say what happened and what to do

Success

“You're in! You are number 4.”

Confirm the result of the action

Disabled

“Joining…” (button disabled)

Prevents double submits

Principle

Visibility of system status: always tell users what is going on, promptly.

Jakob Nielsen, 10 Usability Heuristics for User Interface Design (heuristic #1)
