04

Git

Snapshots and commit IDs

Snapshots, not differences

Subversion tracks changes to each individual file.

Git saves a snapshot of the whole project at every commit. Unchanged files simply point to their previous version.

Result: more redundancy, but faster.

Every commit gets an ID

No global version number, since everyone commits locally. Instead each commit gets a unique SHA-1 hash: 40 hexadecimal characters, usually shown as the first 7.

1677b2d Edited first line of readme
258efa7 Added line to readme
0e52da7 Initial commit

Branches

Branching and merging

main

feature/join-queue

merge commit

git branch          # list; * = current
git branch feature/join-queue
git switch feature/join-queue
# same as: git checkout feature/join-queue
git switch main
git merge feature/join-queue

Git uses branches heavily to switch between tasks: each feature is built on its own branch, then merged.

master or main? Older repos use master. GitHub has named new default branches main since 2020.

Shortcut: git switch -c name creates and switches at once.

11

Branches

Resolving merge conflicts

When both branches changed the same lines, Git marks the file:

<<<<<<< HEAD:index.html
<div id="footer">todo: message here</div>
=======
<div id="footer">
  thanks for visiting our site
</div>
>>>>>>> SpecialBranch:index.html

Top: your current branch's version · bottom: the incoming branch's version

To fix it

  1. Run git status to find conflicted files
  2. Edit each section to the correct version
  3. Delete the <<<, === and >>> lines
  4. git add the file, then git commit

Prevention: pull often and keep branches small.

GitHub is not Git

GitHub.com hosts Git repositories online. Many open-source projects, including the Linux kernel, are mirrored there.

Do you always need GitHub to use Git? No. Git works fully on your own computer, or on any shared server.

Python environments

Why every project gets its own environment

Without: one global Python

Project A needs Flask 2.x; project B needs Flask 3.x. Installing one breaks the other.

“It works on my machine” because nobody knows which packages the app really needs.

With: a virtual environment

project-a/.venv

Flask 2.x

project-b/.venv

Flask 3.x

Each project has an isolated folder with its own packages. requirements.txt lists them so anyone can rebuild it.

venv, pip and requirements.txt

# 1. create (once per project)
python -m venv .venv
# 2. activate (every new terminal)
.venv\Scripts\activate      # Windows
source .venv/bin/activate # macOS/Linux
# 3. install and record
pip install flask
pip freeze > requirements.txt
# 4. rebuild on another computer
pip install -r requirements.txt
deactivate

.gitignore

.venv/
__pycache__/
*.pyc
.env

Commit requirements.txt. Never commit the .venv folder.

Your prompt shows (.venv) when active. Some systems use python3 or py instead of python.

Routes: mapping URLs to Python

app.py

from flask import Flask

app = Flask(__name__)

@app.route("/")
def index():
    return "Hello, CCC181!"

@app.route("/queue/<int:ticket_id>")
def ticket(ticket_id):
    return f"Ticket #{ticket_id}"

$ flask --app app run --debug

@app.route

Connects a URL to the view function below it

Variables in URLs

<int:ticket_id> is passed in as an argument; also string, float, path

HTTP methods

methods=["GET", "POST"] for forms; GET is the default

Open http://127.0.0.1:5000. With --debug, the server reloads on every save.
